# quranEngine.js — محرك تتبع تغطية القرآن

محرك عام مستقل (بدون DOM أو تخزين) لحساب اكتمال الأرباع/الأحزاب/الأجزاء
بدقة كاملة (0 أو 1 فقط لكل ربع)، بناءً على تغطية **كل** آياته فعليًا،
وليس مجرد لمس أول آية فيه (وهو الخطأ الشائع في أغلب الأنظمة المشابهة).

## طريقة الاستخدام

```javascript
const QuranEngine = require('./quranEngine.js');

// 1) مرة واحدة عند تحميل بيانات القرآن (نفس شكل استجابة api.alquran.cloud/v1/meta)
const index = QuranEngine.buildQuranIndex(apiMetaData);

// 2) لكل طالب/مستخدم: أنشئ حالة تغطية فارغة، واحتفظ بها (خزّنها كـ JSON عادي)
const state = QuranEngine.createCoverageState();

// 3) عند كل تسجيل جديد: احسب النطاق ثم سجّله تحت تصنيف حر (اسم يختاره برنامجك)
const stats = QuranEngine.calculateRangeStats(index, /*s1*/2, /*a1*/1, /*s2*/2, /*a2*/141);
QuranEngine.recordCoverage(state, 'جديد', stats.ayahsToProcess);
// يمكن استخدام أي أسماء تصنيفات: 'مراجعة قريبة'، 'مراجعة بعيدة'، إلخ — المحرك لا يفترض عددًا معينًا

// 4) لعرض الإحصائية: اتحاد تصنيف واحد أو أكثر
const stats1 = QuranEngine.getCoverageStats(index, state, ['جديد']);              // حفظ جديد فقط
const combined = QuranEngine.getCoverageStats(index, state, ['جديد', 'مراجعة']);  // الإنجاز الكلي
// combined = { completedQuarters, juzs, hizbs, quarters, totalAyahsCovered }
```

## نقاط مهمة قبل الاستخدام في الإنتاج

1. **التخزين مسؤولية البرنامج المستضيف** — `state.coverage` كائن عادي قابل لـ `JSON.stringify` مباشرة، خزّنه كيفما يناسبك (localStorage، قاعدة بيانات، إلخ).
2. **مصدر بيانات الأرباع:** استخدم دايمًا `data.hizbQuarters.references` من مصدر معتمد (مثال: `api.alquran.cloud/v1/meta`) — لا تُدخل حدود أرباع يدويًا إلا للاختبار.
3. **لماذا ليس حسابًا تناسبيًا (نسبة %):** تم اختباره فعليًا ورُفض — جمع كسور عشرية (`1/طول_الربع`) ثم `Math.floor` يفشل في أكثر من نصف أطوال الأرباع الواقعية بسبب دقة الأعداد الثنائية في JavaScript. هذا المحرك يعدّ أعدادًا صحيحة فقط، فهو محصَّن من هذه المشكلة تمامًا.
4. **البيانات القديمة (قبل استخدام هذا المحرك):** لا يمكن إعادة بناء تغطية دقيقة من أرقام مجمّعة قديمة (عدد آيات فقط، بدون تفاصيل النطاقات). الدقة الكاملة تسري على أي تسجيل جديد بعد تفعيل المحرك فقط.
5. **مُختبر بـ 9 حالات فعلية ناجحة** (`test_final_engine.js` المرفق) — شاملة حالة الخلل الحرج الأصلي (نهاية ربع غير مغطاة كانت تُعتمَد خطأً كـ"مكتمل" في الأنظمة التقليدية القائمة على لمس نقطة البداية فقط).
